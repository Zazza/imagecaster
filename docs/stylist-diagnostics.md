# Геометрия лица и диагностика Стилиста

Дополнительная прорисовка лица проверяет точки лица непосредственно в координатах вырезанного участка. Проверка больше не компенсирует увеличение, сдвиг или поворот перед сравнением. При заметном расхождении результат не вклеивается: остаётся кадр до прорисовки, а статус второго прохода сообщает о пропуске. Это защита от неверной вклейки, а не гарантия правильной анатомии нейросети. Обычная подмена лица выполняется отдельно.

Для новых фотосессий через приложение и синхронный MCP Стилист сохраняет этапы локально в `stylist-diagnostics` рядом с базой данных приложения. При обычном запуске сборки из этого репозитория это `/srv/go-sd/build/bin/data/stylist-diagnostics`.

В каталоге каждого кадра находятся:

- `base.png` — результат генерации до примерки и обработки лица;
- `garment.png` — результат успешной примерки, если она была;
- `face-pass.png` — принятый результат дополнительной прорисовки лица, если она включена и прошла проверку;
- `face-swap.png` — результат успешной подмены лица, если она была;
- `metadata.json` — номер итогового кадра (`frame_id`), названия сохранённых этапов и размеры изображений.

Расширение соответствует фактическому формату ответа: для JPEG и WebP используются `.jpeg` и `.webp`. Номер кадра ищется в `metadata.json`. Сравнение `base` с `garment` и `face-swap` позволяет определить, на каком этапе изменились пропорции. Старые кадры, в том числе 34509, промежуточных изображений не имеют: восстановить их задним числом нельзя. Изменённые варианты существующего кадра через отдельную форму правки в эту диагностику не входят.

По умолчанию сохраняются последние 10 завершённых кадров; лимит 1–50 задаётся в настройках диагностики; более ранние диагностические каталоги удаляются автоматически. Одновременно допускается до 4 записываемых кадров на процесс, размер одного изображения ограничен 16 МиБ. Если этап пропущен, его файла нет. Ошибка диагностики записывается в лог и не отменяет фотосессию. При обычной отмене незавершённый каталог удаляется; после аварийного завершения процесса он может остаться без `metadata.json` и требует ручной очистки.

Файлы не добавляются в галерею, не выдаются через HTTP и не отправляются в облако. Диагностика включается только при локальном SD. На Unix каталоги доступны владельцу (0700), файлы — владельцу (0600); в Windows действуют разрешения файловой системы. Это локальные копии фотографий: для очистки закройте приложение и удалите содержимое `stylist-diagnostics`. Основная история и исходники останутся.

Откат: вернуть вызов прежней проверки геометрии и убрать подключение диагностического регистратора. Формат базы данных и сервер не менялись.

Режимы записи и очистка теперь управляются постоянным разделом [Настройки → Диагностика](diagnostics.md). Подробные логи и полный набор промежуточных изображений по умолчанию выключены; функциональные исходники для восстановления по умолчанию сохраняются отдельно.
