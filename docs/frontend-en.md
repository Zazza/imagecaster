# Imagecaster — Frontend (Vue 3)

Vue 3 (`<script setup>`) + Vite, no router and no store library. Icons: `lucide-vue-next`; fonts: IBM Plex Sans / Mono (`@fontsource`). Code lives in `frontend/src/`.

```
frontend/src/
├── main.js            # mounts App.vue, loads fonts and style.css
├── App.vue            # shell: title bar, sidebar, pages, footer, startup modals
├── api.js             # wrapper over Wails bindings
├── i18n/              # index.js, en.js, ru.js
├── components/        # pages, sections, modals, small widgets
├── composables/       # use* functions
├── *.js               # state modules and pure helpers
├── style.css          # global styles and theme variables
├── wailsjs/           # generated by Wails, do not edit
└── __tests__/         # vitest
```

## App shell (App.vue)

- **Title bar** — `TitleBar.vue`. The window is frameless on Linux and Windows (`Frameless: runtime.GOOS != "darwin"` in `main.go`); `composables/useWindowFrame.js` tracks maximised/fullscreen state and platform.
- **Sidebar** — pages (i18n key → page):

| Key | Label | Component |
|---|---|---|
| `app.nav_generate` | Generate | `UnifiedGeneratePage.vue` → `GeneratePage.vue` |
| `app.nav_postprocess` | Post-Process | `PostProcessPage.vue` |
| `app.nav_gallery` | Gallery | `GalleryPage.vue` |
| `app.nav_my_images` | My Images | `FileBrowserPage.vue` |
| `app.nav_styles` | Styles | `UnifiedPresetsPage.vue` |
| `app.nav_catalog` | Catalog | `CatalogPage.vue` |
| `app.nav_settings` | Settings | `SettingsPage.vue` |

  Sidebar footer: collapse button (state in `localStorage` key `imagecaster_sidebar`), light/dark theme (saved in setting `theme`), RU/EN switch, "Reset All" (`app.reset_all`, two clicks) — clears saved form values of Generate and Post-processing and the last image.
- **Server banner** — shown when the server check is not `ok` and the check window is closed: `server.banner_offline`, `server.banner_outdated` or `server.banner_incompatible`, with the button `server.banner_fix` that reopens the check window.
- **Footer** — `AppFooter.vue`.
- Settings and Catalog stay mounted (`v-show`); other pages are created when opened.

### Startup order

1. `checkServer()` from `serverState.js` (binding `CheckServer`).
2. Not `ok` → `ServerCheckModal.vue`: search the local network (`DiscoverServers`), enter an address manually, "How to install/update the server" link (`server.how_to_install` / `server.how_to_update`), "Retry", "Close" (`server.close_limited`) — the app keeps working in limited mode with the banner.
3. `WelcomeModal.vue` — tabs "What it is" (`welcome.tab_about`) and "What's new" (`welcome.tab_news`, from `releaseNotes.js`). It opens at startup until "Don't show at startup" (`welcome.dont_show`) is ticked; after an update it opens on "What's new"; on a fresh install (no SD models on the server) it opens even if dismissed. The "Models" block offers "Download all for presets" (`settings.btn_download_all`) for the files the bundled styles need (`GetDefaultDownloadPlan`). State: `localStorage` key `imagecaster_welcome`. Clicking the sidebar logo opens it again.
4. `LLMSetupModal.vue` — if `GetLLMSetup().needed`: choose the prompt model and the photo (vision) model; can download the chosen models and save (`SaveLLMChoice`).

## Pages and sections

### Generate
`UnifiedGeneratePage.vue` holds shared state (`provide('sharedGenState')`) and accepts a dropped image file — it opens Post-processing → Remix with that image. `GeneratePage.vue`:
- modes: Style (`generate.btn_style`), Workflow (`generate.btn_workflow`), Custom (`generate.btn_custom`, steps edited in `CustomPipelineEditor.vue`, up to 8 — `customSteps.js`);
- "Generate Image" (`generate.btn_generate`): the LLM writes a prompt from the description (`GenerateSDPrompt`), then the requested number of images (1–100) go to the queue (`EnqueueTxt2Img` / `EnqueueCompound`);
- "Generate Directly" (`generate.btn_generate_directly`): sends the already written prompt right away (`GenerateImage` / `GenerateCompoundImage`);
- saved descriptions and batch of ideas — `SavedDescriptionsModal.vue`, `ideasBatch.js` (up to 20 images per idea);
- `ResolutionSelector.vue`, `HiresProfileSelector.vue`, `PresetOverridesPanel.vue` (per-run overrides of style settings, LoRA weights via `loraOverride.js`), upscale ×2 (`UpscaleImage`);
- form values are saved to settings (`gen_*` keys).

### Post-processing
`PostProcessPage.vue` — one image (or a batch), cards numbered in order:

| # | Title key | Label | Implementation |
|---|---|---|---|
| 01 | `post.section_edit` | Edit | `EditSection.vue`: edit by instruction (`EditImage` / `EnqueueEdit`) or "Describe the look" (`edit.mode_look`: `CompilePostStyle`, `ApplyLookDirect` / `EnqueueLook`); reference image, style, LoRAs |
| 02 | `post.section_remix` | Remix | `RemixSection.vue`: redraw in a style or workflow (`EnqueueFromImage`), photo analysis (`AnalyzeImage`) |
| 03 | `post.section_object` | Object | `ObjectSection.vue`: paint a mask, Remove / Replace (`EditObject`) |
| 04 | `post.section_repair` | Repair | `RepairSection.vue`: mask over damage (`RepairImage`) |
| 05 | `post.effect_title` | Effect | effect styles of types `post`, `post_*` (groups in `effectTypes.js`) via `EnqueueFromImage`; Auto-style (`post.autostyle`, `DescribeForStyle`) |
| 06 | `post.adjust_title` | Correction | local adjustments without AI (`PreviewAdjust`, `AutoAdjust`) |
| 07 | `post.finish_title` | Format, frame, caption | applied on save (`PreviewPost`) |
| 08 | `export.export_settings` | Export Settings | `ExportImage`, saved export presets |
| 09 | `post.recipes_title` | Recipes | saved chains (`RecipeComposition.vue`, `ListPostRecipes` / `SavePostRecipe`) |

Other details: undo/redo of applied steps (Ctrl+Z / Ctrl+Y or Ctrl+Shift+Z), zoom (`useZoomPan.js`), masks (`useMaskCanvas.js`). Batch mode (`postBatch.js`) processes several images sent from My Images or History through the queue; temporary files via `BatchSaveImage`. The page listens to `session:selected` to load the image picked in History.

### Gallery
`GalleryPage.vue` — all history images across sessions (`ListHistory`): filters by session (group), period (`galleryFilters.js`: all / today / week / month / custom), model, style or workflow, type and shape, prompt search; "Load more" paging; selection and delete (`DeleteHistoryItems`); "Open in history" (`gallery.open_in_history`, `OpenInHistory`); viewing in `ImageViewer.vue`.

### My Images
`FileBrowserPage.vue` — browse a local folder (`BrowseDirectory`, `ReadThumbnail`), sort by date or name (`fileSort.js`), pick a folder (`SelectBrowserFolder`), select several and send to Post-processing (`browser.send_to_postprocess_multi`).

### Styles
`UnifiedPresetsPage.vue` with tabs:
- Styles (`unified.tab_presets`) and Effects (`unified.tab_effects`) — `PresetsPage.vue` in modes `styles` / `effects`: filterable table (`presetFilters.js`), editing in `PresetForm.vue`, import (`ImportModal.vue`) / export, installing a style's models (`InstallPresetDeps`);
- Workflows (`unified.tab_pipelines`) — `CompoundPresetsPage.vue`: filterable table (`pipelineFilters.js`), step editing with `SearchableSelect.vue`, import (`PipelineImportModal.vue`), delete with confirmation.

Styles whose model or LoRA is missing on the server are hidden (`presetAvailability.js`, statuses from `SyncPresets` via `composables/usePresets.js`); when the status list is not received, nothing is hidden.

### Catalog
`CatalogPage.vue` — server model catalog (`GetModelCatalog`): download / delete models and LLMs, "Download all for presets", progress in `DownloadProgress.vue`. State in `serverModels.js`.

### Settings
`SettingsPage.vue`, tabs:
- Connection (`settings.tab_connection`) — server address and network search, server processes (start / stop / restart / logs), GPU memory, prompt and photo model choice, LLM parameters (temperature, context, max tokens, top-p, threads);
- Prompts (`settings.tab_prompts`) — editable prompts with defaults from the backend;
- Safety (`settings.tab_safety`) — safe mode (`settings.section_kids`) with PIN (`PinModal.vue`) and categories;
- Advanced (`settings.tab_advanced`) — video memory (`settings.section_memory_guard`, auto-unload LLM), SD/LoRA and LLM model lists on the server.

### Footer
`AppFooter.vue` — service status (`CheckServices`), app version, three panel tabs:
- History (`footer.session`) — items of the current session, session switching (listens to `session:*`);
- Log (`footer.log`) — `GetLogEntries` + `log:entry`;
- Processing (`footer.processing`) — `QueuePanel.vue`: pause / resume, cancel, retry, resume paused (`queue.resume_paused`).

One close button for the open panel. The footer height is saved with `SaveWindowLayout`.

### Shared widgets
`ImageViewer.vue` (full view, zoom, prev/next, delete, send to Post-processing, generation info), `FoldBlock.vue` (collapsible block), `StatusMessage.vue`, `ToggleSwitch.vue`, `SearchableSelect.vue`, `DownloadProgress.vue`.

## api.js

- Imports bindings from `wailsjs/go/main/App.js` and exports one `api` object with camelCase methods; some add defaults or build param objects (e.g. `generateImage(presetId, extraPrompt, …)` → `GenerateImage({preset_id, …})`).
- `sessionImageUrl(id)` / `sessionThumbUrl(id)` return `/api/img/<id>.jpg` / `/api/thumb/<id>.jpg`.
- `downloadServerModelStream` / `pullServerLLMModelStream` create a job id, subscribe to `server:download:progress:<jobID>` and parse progress with `downloadProgress.js`.
- Server calls (generation, analysis, edits, `enqueue*`, `retryQueueJob`) are wrapped by `serverGate.js`: while the server check is not `ok` they reject with `server.need_server`.
- Bindings: see [api-reference-en.md](api-reference-en.md).

## i18n

- `i18n/index.js`: `t(key, params)`, `setLocale(l)`, `locale`. Lookup order: current language → English → the key itself. Parameters are written as `{name}` in strings.
- Languages: `ru` (default) and `en`. The choice is stored in `localStorage` key `ui_locale` and also sent to the backend as setting `ui_locale`.
- `en.js` and `ru.js` have the same 1079 keys, grouped by prefix (`app.`, `generate.`, `post.`, `settings.`, `gallery.`, `queue.`, `server.`, `welcome.`, …).
- Rule: every user-visible string goes through `t()` and is added to both files.

## Theme

`style.css` defines variables on `:root` (dark) and `[data-theme="light"]`: `--bg`, `--surface`, `--border`, `--text`, `--text-bright`, `--text-dim`, `--accent`, `--accent-hover`, `--danger`, `--warning`, `--success`, `--radius`, `--font-sans`, `--font-mono` and others. The theme is set by `data-theme` on `<html>`.

## Tests

- Vitest + `@vue/test-utils`, environment `happy-dom` (`frontend/vitest.config.js`, setup file `src/__tests__/setup.js`).
- Run: `cd frontend && npm test` (`vitest run`), watch mode `npm run test:watch`.
- 75 test files in `src/__tests__/`, by area: Generate, Post-processing (effects, batch, finish, live preview, masks), Gallery, Styles and Workflows tables, Catalog, Settings, server check, welcome and LLM setup, queue, footer, image viewer, sidebar, i18n of some texts.
- Mocks: tests replace bindings with `vi.mock('../wailsjs/go/main/App.js', …)` — usually `mocks/wails-app.js` (all bindings as `vi.fn`) — and runtime with `vi.mock('../wailsjs/runtime/runtime', () => import('./mocks/runtime'))`; `mocks/runtime.js` keeps real listeners and has `EventsEmit` to fire events in tests.
