# Imagecaster — Архитектура

Imagecaster — десктопное приложение. Модели оно само не запускает: генерация картинок и вся работа ИИ с текстом (промпты, описания фото) идут на **Imagecaster Server** — отдельной программе ([imagecaster-server](https://github.com/Zazza/imagecaster-server)) на этом или другом компьютере в локальной сети.

## Стек

| Слой | Технология |
|------|-----------|
| Бэкенд | Go 1.25, модуль `github.com/Zazza/imagecaster` |
| Десктоп | Wails v2 |
| Фронтенд | Vue 3 + Vite |
| База данных | SQLite, `modernc.org/sqlite`, чистый SQL (без ORM) |
| Картинки | stable-diffusion.cpp на сервере |
| Текстовая и vision-модель | llama.cpp на сервере |
| Точки лица и позы | ONNX Runtime + DWPose на сервере |

Из репозитория собираются два бинарника:

| Бинарник | Исходники | Назначение |
|----------|-----------|-----------|
| `imagecaster` | `main.go`, `app.go` | приложение с интерфейсом |
| `imagecaster-mcp` | `cmd/imagecaster-mcp` | MCP-сервер для ИИ-агентов (stdio, JSON-RPC) |

## Схема

```
┌──────────────────────── компьютер ───────────────────────┐
│                                                           │
│  Vue 3 UI ──Wails bindings──▶ App (app.go)                │
│     ▲                          │                          │
│     └──── события Wails ◀──────┤                          │
│                                ▼                          │
│        generation · queue · session · settings · ...      │
│                │                        │                 │
│                ▼                        ▼                 │
│         sd / llm / serverclient     SQLite + data/        │
│                │                        ▲                 │
│  imagecaster-mcp ───────────────────────┘ (та же БД)      │
└────────────────┼──────────────────────────────────────────┘
                 │ HTTP (локальная сеть)
                 ▼
┌──────────── Imagecaster Server (порт по умолчанию 8080) ──┐
│  GET /                 имя, версия, возможности           │
│  /api/sd/...           задания картинок (sd.cpp)          │
│  /api/llm/...          чат и vision (llama.cpp)           │
│  /api/server/...       статус, модели, загрузки, логи     │
└───────────────────────────────────────────────────────────┘
```

## Карта модулей

### Корень

| Файл | Роль |
|------|------|
| `main.go` | Читает конфиг, открывает БД, создаёт клиенты, восстанавливает адрес сервера, запускает Wails. Отдаёт интерфейсу картинки истории по `/api/img/<id>` и миниатюры по `/api/thumb/<id>`. |
| `app.go` | `App` — фасад. Каждый Wails binding — экспортируемый метод `*App`. Здесь связываются все сервисы. |

### `internal/`

| Пакет | Роль |
|-------|------|
| `adjust` | Коррекция пикселей: уровни, яркость, контраст, насыщенность, температура, резкость, виньетка; автоанализ (`AnalyzeAuto`). |
| `batch` | Временная папка `data/batch` для пакетного сохранения; очищается при запуске. |
| `clipboard` | Чтение картинки из буфера обмена. |
| `config` | Структура `Config`, промпты по умолчанию, разрешённые ключи настроек, лимит размера картинки (128 МБ). |
| `faceguard` | Работа с лицом по точкам: вклеивает глаза, нос и губы с исходного фото в отредактированное, отклоняет чужое лицо, ретушь. Используют стилист и MCP-фоторедактор. |
| `filebrowser` | Список папок, чтение картинок и миниатюр для страницы «Мои изображения». |
| `finish` | Формат (обрезка или вписывание в пропорцию), рамка и подпись. |
| `generation` | Основной сервис: генерация промпта, txt2img, пайплайны, «из картинки», правка, удаление/замена объекта, восстановление, эффекты, образ (look), рецепты постобработки, описания фото. |
| `importexport` | Импорт/экспорт стилей и пайплайнов; экспорт картинки (формат, размер, оформление). |
| `kids` | Детский режим: PIN, категории контента, фильтры входного текста, ответа ИИ и негативного промпта. |
| `llm` | HTTP-клиент к LLM сервера (`/api/llm`). |
| `logger` | Журнал приложения: кольцевой буфер на 500 записей, событие `log:entry`, перехват стандартного `log` Go. |
| `maskcomp` | Работа с маской: вклейка изменённой области в оригинал, смешивание, контур, сохранение цвета. |
| `mcp` | MCP-сервер: инструменты, промпты `stylist` и `photo_editor`. |
| `preset` | Репозиторий SQLite: стили, пайплайны, настройки, сессии/история, разрешения, hires-профили, пресеты экспорта, рецепты постобработки; миграции схемы; встроенные пресеты. |
| `promptutil` | Чистка ответов ИИ: извлечь JSON, убрать мусор, убрать повторы тегов. |
| `queue` | Постоянная очередь заданий (таблица `job_queue`) с повторами и паузой. |
| `sd` | Клиент заданий картинок сервера (`/api/sd/jobs`), списки моделей, точки лица. |
| `sdnames` | Переводит старые имена сэмплеров, планировщиков и апскейлеров из прежних версий в имена stable-diffusion.cpp. |
| `serverclient` | Проверка сервера, поиск по mDNS, управление моделями и потоки загрузки, встроенный каталог моделей. |
| `session` | История картинок: сессии, элементы, файлы на диске, события; следит за изменениями БД, сделанными `imagecaster-mcp`. |
| `settings` | Настройки, проверка сервера, адрес сервера, загрузка моделей, выбор моделей ИИ, синхронизация пресетов. |

### `cmd/imagecaster-mcp`

Отдельный процесс, его запускает MCP-клиент. Открывает тот же `presets.db`, собирает тот же сервис `generation` и работает с тем же сервером. Картинки кладёт в сессии приложения («ИИ-агент», «Стилист», «Фоторедактор»); запущенное приложение видит их, опрашивая БД раз в 2 с. Файлы также пишутся в `~/imagecaster-mcp-out` (или `IMAGECASTER_MCP_OUT`). Очередь заданий не использует.

Фото не покидают локальную сеть: инструменты для фото отказываются работать, если адрес сервера не локальный (loopback, частный или link-local IP), и отдают только текст, который выдала локальная vision-модель сервера.

### `frontend/`

| Путь | Роль |
|------|------|
| `src/App.vue` | Оболочка: боковое меню, страницы, нижняя панель, окна первого запуска. |
| `src/components/` | Страницы и виджеты (Генерация, Постобработка, Галерея, Мои изображения, Стили, Каталог, Настройки, панель очереди, модальные окна). |
| `src/composables/` | Общее состояние: `useQueue`, `usePresets`, `useGenerationProgress`, `useKidsMode`, `useMaskCanvas`, `useZoomPan`, `useWindowFrame`. |
| `src/api.js` | Тонкий слой над Wails bindings; подписка на события прогресса загрузки. |
| `src/i18n/` | Строки на русском и английском. |
| `src/wailsjs/` | Сгенерированные Wails bindings — не править. |

## Как приложение работает с сервером

### Подключение

- Одна настройка: `server_url`. Адреса SD и LLM выводятся из неё: `<server_url>/api/sd` и `<server_url>/api/llm`.
- Поиск: mDNS-сервис `_imagecaster._tcp`; адрес можно ввести вручную. Порт сервера по умолчанию 8080.
- Проверка при запуске (`CheckServer`): `GET /` должен вернуть имя `Imagecaster Server` и возможности `sdcpp`, `download_stream`, `sd_jobs`, `llamacpp`. Итог: `ok`, `not_configured`, `not_found` или `outdated` (со списком недостающего). При любом итоге кроме `ok` интерфейс показывает окно; если его закрыть, приложение работает в ограниченном режиме.

### Задания картинок

- Каждая операция с картинкой — задание на сервере: `POST /api/sd/jobs` с `kind` (`txt2img`, `img2img`, `upscale`), параметрами и своей моделью (checkpoint, VAE, модули). Общей «текущей модели» для приложения на сервере нет.
- Клиент опрашивает `GET /api/sd/jobs/<id>`, затем забирает `GET /api/sd/jobs/<id>/result`. Прогресс уходит в интерфейс событием `sd:progress`.
- У каждого задания есть `client_ref`, он начинается с ID установки. «Прервать» отменяет незавершённые задания этой установки (`POST /api/sd/jobs/<id>/cancel`).
- Потерянное задание (статус `lost`, или `failed` с `server_restarted`, или 404) отправляется заново один раз.
- На сервере: одна очередь GPU для картинок и LLM с бюджетом памяти от VRAM; результаты хранятся 24 ч; задания, не завершённые к перезапуску сервера, заканчиваются ошибкой `server_restarted`.

### Задания очереди переживают перезапуск

- Шаги задания очереди приложения используют `client_ref` = `<install_id>:q<id очереди>:s<шаг>:<hash>`. Сервер по тому же ref отдаёт уже существующее задание, поэтому после перезапуска приложения шаг продолжается, а не начинается заново.
- Ответы ИИ внутри задания очереди сохраняются в `data/queue-llm/<id>.json` и берутся оттуда при повторе.
- Закрытие приложения задания на сервере не отменяет.

### LLM

Клиент LLM обращается к серверу по `/api/llm`: OpenAI-совместимый `/v1/chat/completions` для текста, `/api/chat` с картинками для vision, а также методы списка моделей, загруженных моделей и выгрузки.

### Загрузка моделей

Модели скачивает сервер. Приложение открывает поток (`/api/server/models/download/stream`, `/api/server/models/llm/pull`), читает строки `data:` до `[DONE]` или `[ERROR] …` и пересылает каждую строку в интерфейс событием `server:download:progress:<jobID>`. Если связь оборвалась — ошибка «connection to server lost».

## Данные на диске

Всё рядом с БД (по умолчанию `data/` возле исполняемого файла, или `DB_PATH`):

| Путь | Содержимое |
|------|-----------|
| `presets.db` | база SQLite |
| `sessions/<сессия>/` | картинки сессий истории |
| `thumbs/<сессия>/` | миниатюры |
| `queue-llm/<id>.json` | ответы ИИ задания очереди |
| `batch/` | временные файлы пакетного сохранения |

## Принципы

- **Фасад:** фронтенд вызывает только методы `App`.
- **Интерфейсы для внешних сервисов:** `llm.Service`, `sd.Service` — в тестах подменяются заглушками.
- **Внедрение через конструкторы:** функции `New*`; сборка в `main.go` / `NewApp` и в `cmd/imagecaster-mcp/main.go`.
- **Репозиторий:** `preset.DB` скрывает SQL.

## Тесты

- Go: `go test ./...` (табличные тесты, `httptest`-серверы для клиентов, SQLite в памяти).
- Фронтенд: `cd frontend && npm test` (Vitest).
