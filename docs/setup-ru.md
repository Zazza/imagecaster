# Imagecaster — установка

Imagecaster — это две программы:

- **Imagecaster Server** ([репозиторий](https://github.com/Zazza/imagecaster-server)) работает на компьютере с видеокартой. Он сам ставит и запускает stable-diffusion.cpp (картинки) и llama.cpp (текстовые модели и модели, читающие фото), скачивает модели и пропускает все запросы к видеокарте через одну очередь.
- **Imagecaster** (это приложение) работает на том же компьютере или на любом другом в локальной сети. Всю работу с ИИ оно делает через сервер.

Сначала ставится сервер.

## Установка сервера

Скачайте архив для своей системы со страницы [релизов сервера](https://github.com/Zazza/imagecaster-server/releases) и распакуйте куда угодно. Рядом с каждым архивом лежит файл `.sha256`.

| Система | Архив | Внутри |
|---|---|---|
| Windows x64 | `imagecaster-server-<версия>-windows-amd64.zip` | `imagecaster-server.exe` (окно установки, потом значок в трее), `imagecaster-server-console.exe` (терминальный интерфейс) |
| Linux x64 | `imagecaster-server-<версия>-linux-amd64.tar.gz` | `imagecaster-server` |
| macOS arm64 (Apple Silicon) | `imagecaster-server-<версия>-darwin-arm64.tar.gz` | `imagecaster-server`, `Imagecaster Server.command` |

**Windows.** Запустите `imagecaster-server.exe`. Окно установки показывает видеокарту, спрашивает папку данных (любой диск со свободным местом) и после **Установить** ставит всё. Когда появится **Готово**, окно можно закрыть: сервер продолжит работать, его значок — в трее. В меню значка: состояние движков, адрес для приложения (щелчок копирует), **Панель управления**, журнал и **Выход**. В следующий раз просто снова запустите `imagecaster-server.exe`.

**Linux.**

```bash
tar xzf imagecaster-server-*-linux-amd64.tar.gz
cd imagecaster-server-*-linux-amd64
./imagecaster-server
```

Первый запуск спрашивает папку данных (Enter — по умолчанию `~/imagecaster-server`), ставит всё и показывает панель в терминале. Сборкам для Linux нужна `libssl.so.3`.

**macOS.** Откройте `Imagecaster Server.command` (в первый раз: правый клик → «Открыть»). Он снимает карантин загрузки с сервера и запускает его в «Терминале»; дальше всё как в Linux. На Mac сборка ещё не проверялась.

Сервер ничего не прописывает в систему и не стартует вместе с ней: запускаете его, когда нужно.

### Требования

- Видеокарта NVIDIA со свежим драйвером (сборка CUDA 12); другие видеокарты — сборка Vulkan, Mac — Metal. Без видеокарты генерация идёт на процессоре и очень медленно.
- Для Linux ARM, Windows ARM и Mac на Intel нет сборки stable-diffusion.cpp — генерации картинок там нет.
- Диск: около 8 ГБ на движки плюс модели.
- Интернет при первом запуске.

### Что ставит первый запуск

- stable-diffusion.cpp — сборку под вашу видеокарту;
- llama.cpp — текстовые модели и модели, читающие фото;
- ONNX Runtime и модели DWPose — точки лица и позы.

Модели картинок и модели ассистента здесь **не** скачиваются — это делает приложение (см. [Модели](models-ru.md)). Оборванная загрузка продолжается с места обрыва.

### Папка данных

Всё, что есть у сервера, лежит в одной папке:

```
<data>/
  server-config.yaml
  engines/sd-cpp-<ОС>/       stable-diffusion.cpp
  engines/llama-cpp-<ОС>/    llama.cpp
  engines/onnxruntime/       ONNX Runtime
  models/checkpoints/        модели картинок
  models/text_encoders/      энкодеры текста и токенизаторы
  models/vae/
  models/loras/
  models/upscalers/
  models/openpose/           модели DWPose
  sdjobs/                    результаты заданий на картинки (хранятся 24 часа)
```

Какая папка берётся: `--data DIR`, иначе выбранная при первом запуске, иначе `~/imagecaster-server`.

### Запуск службой

`imagecaster-server --headless` работает без интерфейса и пишет журнал в stdout — для службы systemd. Тот же режим включается, если stdin — не терминал. API отвечает сразу, установка идёт в фоне.

| Флаг | Что делает |
|---|---|
| `--data DIR` | папка данных |
| `--config FILE` | файл настроек (по умолчанию `<data>/server-config.yaml`) |
| `--port N` | порт API (по умолчанию 8080) |
| `--headless` | без интерфейса, журнал в stdout |
| `--version` | показать версию |

`imagecaster-server attach [хост[:порт]]` открывает панель уже запущенного сервера — на этом компьютере или на другом.

### Порты

| Порт | Кто слушает | Кому нужен |
|---|---|---|
| 8080 | сервер (все интерфейсы) | приложению — это адрес для подключения |
| 7860 | сервер | другим программам, которые обращаются к stable-diffusion.cpp напрямую; запросы всё равно идут через очередь видеокарты |
| 11434 | сервер | другим программам, которые пользуются текстовыми моделями; запросы всё равно идут через очередь видеокарты |
| 7861, 11435 | stable-diffusion.cpp, llama.cpp | только loopback, из сети недоступны |

Сервер объявляет себя в локальной сети по mDNS (`_imagecaster._tcp`), поэтому приложение находит его без ввода адреса.

Полная документация сервера: [README](https://github.com/Zazza/imagecaster-server/blob/main/README-ru.md), [docs/server-ru.md](https://github.com/Zazza/imagecaster-server/blob/main/docs/server-ru.md).

## Установка приложения

Скачайте архив со страницы [релизов приложения](https://github.com/Zazza/imagecaster/releases). Установщика нет: распакуйте и запустите.

| Система | Архив | Внутри | Нужно |
|---|---|---|---|
| Windows x64 | `imagecaster-windows-amd64.zip` | `imagecaster.exe`, `imagecaster-mcp.exe` | WebView2 (встроен в Windows 10/11) |
| Linux x64 | `imagecaster-linux-amd64.tar.gz` | `imagecaster`, `imagecaster-mcp` | GTK 3 и WebKitGTK 4.1 |
| macOS arm64 (Apple Silicon) | `imagecaster-darwin-arm64.tar.gz` | `imagecaster.app` (`imagecaster-mcp` внутри `Contents/MacOS`) | — |

- Сборки не подписаны. Windows SmartScreen может предупредить при первом запуске («Подробнее» → «Выполнить в любом случае»). Если macOS не открывает приложение, снимите флаг карантина: `xattr -dr com.apple.quarantine imagecaster.app`.
- Данные приложение хранит в папке `data` рядом с программой: база `presets.db`, картинки истории (`sessions/`). Распаковывайте туда, где есть право записи. Переменная окружения `DB_PATH` переносит базу (и папку вместе с ней).
- `imagecaster-mcp` — MCP-сервер для ИИ-агентов. Он работает с той же базой, поэтому запускайте его под тем же пользователем, что и приложение.

## Первый запуск приложения

Приложение показывает до трёх окон, по порядку.

1. **Проверка сервера** — только если сервер не задан, не отвечает или устарел.
   - Окно ищет серверы в локальной сети и показывает найденные; подключение — одним щелчком.
   - Или введите адрес, например `http://192.168.1.100:8080`.
   - Если сервер слишком старый, окно говорит, чего не хватает, и ведёт на инструкцию по обновлению. Модели, которые уже есть на сервере, заново не скачиваются.
   - **Проверить снова** повторяет проверку. **Закрыть** открывает приложение в ограниченном режиме: полоса сверху сообщает, что сервера нет; история, просмотр файлов и постобработка без ИИ работают. Кнопка на полосе снова открывает проверку.
2. **Приветствие** — что это за приложение и блок **Модели**: он проверяет, каких файлов не хватает встроенным стилям, показывает их число и общий размер и даёт кнопку «Скачать всё для пресетов». Файлы скачиваются на сервер; окно можно закрыть, загрузка продолжится. После обновления приложения вместо этого окно показывает «Что нового». «Больше не показывать при запуске» скрывает его; та же загрузка есть на странице «Каталог».
3. **Модели ИИ-помощника** — если модель для промптов не выбрана или её нет на сервере. Два списка: модель для промптов и модель для фото. У каждого варианта видно, установлен ли он, размер загрузки и какой рекомендован. «Скачать и сохранить» или «Позже».

Стили появляются сами: получив список моделей с сервера, приложение ставит встроенные стили для тех моделей, что есть на сервере. Стили без своей модели или LoRA скрыты.

Адрес сервера потом меняется в «Настройки» → «Подключение».

## Сборка из исходников

Нужны [Go](https://go.dev/dl/) 1.25+, [Node.js](https://nodejs.org/) 20+ и [Wails CLI](https://wails.io/) v2.

| Система | Дополнительно |
|---|---|
| Windows | WebView2 |
| Linux | `libgtk-3-dev`, `libwebkit2gtk-4.1-dev` |
| macOS | Xcode command line tools (`xcode-select --install`) |

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@latest
git clone https://github.com/Zazza/imagecaster.git
cd imagecaster
make setup   # модули Go и пакеты npm
make dev     # запуск с горячей перезагрузкой (wails dev)
make build   # build/bin/imagecaster
make mcp     # build/bin/imagecaster-mcp
make test    # go vet, go test, сборка фронтенда
```

`make build` вызывает `wails build` и вшивает в программу версию из последнего git-тега. В Linux он добавляет `-tags webkit2_41`, чтобы приложение собиралось с WebKitGTK 4.1; голому `wails build` нужен тот же флаг.

Тесты фронтенда: `cd frontend && npm test`.
