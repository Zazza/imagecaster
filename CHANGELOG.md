# Changelog

All notable changes to Imagecaster are documented here.

## [Unreleased]

### Removed
- **Remix tab merged into Post-Process**: the standalone Remix page is gone — its whole toolkit (gen mode Style/Workflow, img2img/inpaint/remove-object, denoise slider, seed, resolution/hires/overrides, quality mode, preserve-face for klein, LLM tags/description analysis, extra negatives, folder batch "Folder: N photos", batch count, progress with interrupt and fi_* persistence) lives in the new "Remix" accordion section of Post-Process; the sidebar keeps one "Post-Process" link under Refine (`app.nav_remix` i18n key removed, `post.section_remix` added). The source panel is the Post-Process preview itself: the section takes the current image as its source and returns the result onto the current layer; loading the first photo of a folder batch replaces the page source. Inpaint mask is drawn right on the before/after preview (drag = brush with a circle cursor, pan disabled, Ctrl+wheel zoom kept; the mask canvas transforms with the layers) and survives same-size regeneration; switching the source or leaving inpaint clears it. Dropping an image on the Generate page now opens Post-Process (Remix section) with it as the source (new `initialImage` prop, same pattern as the section deep-link); File Browser "→ Remix" single/multi and the viewer's Remix action deep-link to the section, and Unified Generate keeps a single Generate tab.

### Changed
- **Post-Process: effect gallery grouped by subtype**: the Effect section now collects presets from all five effect types (`post`, `post_material`, `post_skin`, `post_light`, `post_film` — 41 presets total) and renders them as five labelled groups in a fixed order (Basic → Materials → Skin → Light → Film; new `post.group_effect_*` i18n keys, ru/en) instead of one flat `post` grid; group headers are small dim uppercase labels in the style of the sidebar ones, the 2-column card grid and the "No effect" card (above all groups) are unchanged, and the selected effect keeps tracking the preset id. The 25 new effects got Russian labels via the existing `post.effect_<slug>` mechanism (`post.effect_leather` «Кожа» … `post.effect_cross_process` «Кросс-процесс»); Portra 400 and Super 8 deliberately have no keys — their Russian label equals the DB name, so the fallback shows them as-is.
- **Sidebar regrouped into five sections** (phase 1 of the Post-Process redesign): Create (Generate), Refine (Remix, Edit, Post-Process), View (Compare, My Images), Library (Styles), Setup (Settings) — group labels come from the new `app.group_*` i18n keys (ru/en); links, icons and active states are unchanged.
- **Post-Process: accordion right panel**: the Effect and Correction cards are now collapsible with exactly one open at a time (Effect by default) — a chevron in the card header rotates, the body collapses via a height animation (no libs), the panel soft-scrolls the newly opened card into view, and the "Reset all" button no longer toggles the section.
- **Post-Process: zoom/pan in the before/after split preview** (ImageViewer mechanics): Ctrl+wheel steps zoom ±10% (plain wheel keeps scrolling), a corner row offers [−][Fit|NN%][+] with a preset menu (Fit/30/50/100, range 10–500%), double-click toggles fit/100%, and the zoomed view can be dragged to pan with clamped bounds (viewport tracked on resize). Both layers share one transform while the curtain clip and divider stay screen-space; the curtain is now dragged only by its handle (the rest of the preview pans), a >4px drag suppresses the double-click, and changing the image (new effect result/adjust preview) resets to fit.
- **Post-Processing: Photoshop-style layout**: the page is now a fixed-height workspace — the before/after split preview fills the left side and stays visible while you scroll, and the Effect + Correction cards live in an independently scrolling 360px panel on the right (effect cards compacted into a 2-column list). Export settings, export presets and the folder conveyor card moved below the workspace at full width. Split-slider mechanics, drop/paste source and pipeline states are unchanged.
- **Post-Processing: localized effect names**: the 16 effect cards show Russian names (Satin Gloss → «Сатиновый глянец» etc.) with the original English preset name as a small subtitle and tooltip, so cards still match the library; unknown effects fall back to the raw DB name. English locale keeps the original names.

### Fixed
- **Post-processing security/logic fixes (review)**: image inputs are size-checked via a header-only `DecodeConfig` pass before full decode in both `PreviewAdjust` and `ProcessExportImage` — a decompression bomb (e.g. a 33-byte PNG header claiming 60000×60000) or an unreadable header is rejected with "image too large" before any pixel allocation; `WriteImageToPath` no longer silently overwrites existing files (writes with `O_EXCL` and auto-suffixes `_1`, `_2`… before the extension, returning the actual saved path to the frontend); export filenames pass through `SanitizeFilename` (which now also strips control characters), and the dialog save branch flattens the filename with `filepath.Base` like the OutputDir branch; levels with black==white can no longer produce a NaN LUT (span widened to ≥1); `ExportSessionItem` errors are wrapped once ("export session item: …" instead of a doubled "session item not found: session item not found").

### Added
- **"Describe the look" hybrid (frontend for `ApplyLookDirect`)**: the look mode in the Edit section of Post-Process now has a way switcher — "Preset effects" | "Free-form (Klein)" (segmented mode buttons like Remix, persisted as `edit_look_mode` in settings, default `effects`, reset by "Reset all"). Effects mode is the old compile→composition→Apply/Save flow unchanged; free mode shares the same textarea, adds a strength slider (0.35–0.65, default 0.5) and a single Apply button that emits `apply-look {text, strength}` — the page owns the engine: one `lookBusy` state joins the existing busy guards (effect/recipe/pipeline buttons disable while a look runs), `api.applyLookDirect` result lands on the current layer via the shared `onToolResult` (layer history + dimension measure), the effective prompt is shown back in the section ("Prompt: …" line via the `look-result-prompt` prop), and `preserve_identity_reset_failed` raises the existing warning notice. Recipe/journal integration: the applied-effects journal now also holds free steps `{prompt, strength}` (no `preset_id`), "Save as recipe" serializes them as-is (backend accepts prompt steps), `applyRecipe` runs free steps synchronously via `ApplyLookDirect` between queue steps (interrupt honoured between steps by the existing `recipeCancelled` flag), and `RecipeComposition` renders prompt steps as "Prompt: <first 40 chars>…" chips with the full text in the tooltip. New i18n keys `edit.look_mode_effects(_hint)`, `edit.look_mode_free(_hint)`, `edit.look_strength`, `edit.look_prompt_label`, `post.recipe_prompt_step` (ru/en); `edit_look_mode` added to `AllowedSettings`.
- **"Free-form (Klein)" look backend**: new `ApplyLookDirect(imageBase64, text, strength, seed)` binding — a direct pass for "Describe the look": the text is rewritten by the text LLM into a short English prose look prompt (temperature 0.3, one retry on an empty reply, reply trimmed and capped at 500 runes; on a full LLM failure the original text is used as the prompt with a log warning, so the feature never dies on the LLM), then the photo goes through klein reference img2img (`flux-2-klein-4b.safetensors` with its TE/VAE modules via `setModel`, `klein_do_reference` enabled under `referenceMu` with rollback on a failed enable and a deferred disable flagged through `PreserveIdentityResetFailed`), fixed live contract Euler/Simple/8 steps/CFG 1.0, strength clamped 0.35–0.65 (clamp, not error), source dimensions aligned to /8 and capped at 2048 on the larger side, result added to the session as source `look` with meta `Look: <text≤60>`. Validation is a pure `validateLookParams` helper; the LLM rewrite, reference sequence, strength clamp, kids-mode block and LLM-failure fallback are covered by tests.
- **Post-Processing UI for the style assistant (frontend stage 3 of 3)**: three user-facing pieces wire up the `AutoAdjust`/`DescribeForStyle`/`CompilePostStyle` bindings (api.js wrappers `autoAdjust`/`describeForStyle`/`compilePostStyle`). (1) "Auto levels"/"Auto WB" buttons beside "Reset all" in Correction — levels set black point/white point/gamma, WB sets temperature (the existing preview watch refreshes the split), errors land in the page notice, both disabled without an image. (2) "✨ Auto-style" button in the Effect card header: analyzes the photo via the vision model, compiles a recipe (spinner + "Analyzing photo…" for the LLM wait), then shows a compact composition panel (vision text, effect steps "Name strength", active corrections) with Apply/Cancel — Apply feeds the existing recipe engine (`applyRecipe`), so the applied-effects journal fills and "applied → saved" keeps working. (3) A second mode in the Edit section — "Edit by instruction" | "Describe the look" (mode not persisted, instruction is the default): in look mode the instruction-specific blocks (garment, style, LoRA, quality) are hidden and a textarea + "Compile recipe" produce the same composition panel with "Apply" (runs the chain on the page via the new `apply-recipe` emit) and "Save as recipe" (name input prefilled with the description capped at 60 chars, saved directly through `SavePostRecipe` bypassing the journal via the new `save-recipe` emit). New shared `RecipeComposition.vue` renders the recipe makeup; new i18n keys `post.auto_levels`, `post.auto_wb`, `post.autostyle`, `post.autostyle_analyzing`, `post.autostyle_apply`, `post.autostyle_vision`, `post.composition`, `edit.mode_instruction`, `edit.mode_look`, `edit.look_label`, `edit.look_placeholder`, `edit.look_compile`, `edit.look_apply`, `edit.look_save`, `edit.look_name_placeholder` (ru/en).
- **LLM style assistant, backend stage 2 of 3**: two new bindings turn a free-form look description into a post-processing recipe. `CompilePostStyle(text)` builds the effect catalog live from the five effect types (`post`, `post_material`, `post_skin`, `post_light`, `post_film` — resolved via `preset_types`, new `ListByTypeIDs` query), prompts the text generate model (temperature 0.2, one retry on unparseable JSON) with an abstract compiler instruction listing each effect as `name — first phrase of its prompt` grouped by family plus the 12 adjustment ranges, and fail-soft-validates the reply: effect names matched case-insensitively against the catalog (unknown dropped, duplicates merged, max 3 steps), strength clamped 0.35–0.65, adjustment fields clamped to their ranges with unknown keys dropped; a fully empty result errors with "could not compile a recipe from this description". `DescribeForStyle(imageBase64)` runs the vision model (`llm_analyze_model`, same path as AnalyzeImage) for a 1–2 sentence scene summary (subject, clothing, lighting, mood, colors) to feed the compiler — both apply the kids filter (input for the text, output for the description) and the 16 MB image cap. Validation/clamp logic is a pure `parseAndValidate` function covered by table-driven tests without an LLM. Frontend comes in stage 3.
- **Auto-correction analysis (backend stage 1 of 3)**: new `AutoAdjust(imageBase64)` binding returns histogram-derived correction parameters (`internal/adjust/auto.go`, no LLM) for the future "Auto levels"/"Auto WB" buttons in Post-Process — levels from the Rec.601 luma histogram over opaque pixels (0.2% end-cuts, black clamped to 0–80, white to 175–255, raw span <40 → neutral 0/255; gamma = ln(norm)/ln(0.5) of the normalized median, clamped 0.6–1.8, snapped to 1 within ±0.05) and gray-world temperature ((meanB−meanR)/avg·260, rounded, clamped ±60; R +15% over B → t≈−36). Images over 1 MP are analyzed on a deterministic every-2nd-pixel grid; degenerate inputs (nil, empty, fully transparent, 1×1) return the neutral {0, 255, 1, 0} without panic. The math is pinned by table-driven tests (dark/overexposed/warm/cold/neutral/sampling equivalence).
- **Post-processing recipes (backend stage)**: the effect chain (klein-effect steps with strength) plus the pixel-correction block can now be saved as a named recipe and re-applied later — new `post_recipes` table (migration V29; `steps` JSON array `[{"preset_id":N,"strength":F}]`, `adjust` JSON object), CRUD in `internal/preset/recipe.go` (name trimmed and capped at 100 chars, steps/adjust must be valid JSON ≤8192 bytes — fail-closed) and three facade bindings: `ListPostRecipes`, `SavePostRecipe` (insert at id 0, update otherwise; update of a missing id errors), `DeletePostRecipe` (idempotent). Frontend comes in a separate stage.
- **Post-Process: mask overlay toggle, stroke redo, layer undo/redo**: the mask preview gains an eye button in the zoom row (visible only in mask mode) that hides/shows the mask overlay without stopping the brush — paint blind is a user choice; the Remix mask tools get a "Redo" button next to "Undo" (a new stroke, clear or source switch empties the redo stack, undo pushes the pre-undo canvas into it), and the page keeps a 15-step layer history (Undo2/Redo2 buttons in the zoom row) recorded before every layer replacement — edit/remix/effect results, remix source switches and "Restore original" — with adjust previews and zoom/pan excluded; Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y (also via KeyZ/KeyY codes for non-Latin layouts, ignored while typing in inputs) route to mask undo/redo in mask mode and to layer undo/redo otherwise, and loading a fresh image resets the layer history while a remix source switch keeps it. New i18n keys `post.undo`, `post.redo`, `post.mask_show`, `post.mask_hide`, `fi.btn_redo` (ru/en).
- **"To Post-Process" buttons on every result panel**: Generate, Remix and Edit result action rows gain a "To Post-Process" button — it activates the just-generated session item and opens the Post-Process tab with it loaded (the same navigate-and-activate idiom as the fullscreen viewer's actions; navigation is wired through the Unified Generate wrapper). Compare is untouched (its compared variants are in-memory test results without session items).
- **Post-processing tab (effect → adjustments → export)**: a new "Post-Process" tab replaces Export and runs a fixed three-stage pipeline over a photo. **Stage 1 — Effect** (optional): a gallery of 16 klein reference presets (Satin Gloss, Film Real 35mm, Golden Hour, Evening Mood, Night City Neon, B&W Film, Vintage 70s, Cinematic Teal-Orange, Shallow DOF, Soft Studio, Flash Photo, Color Pop, Soft Glow, Moody Dark, Crisp Reality, Bright & Airy) plus "No effect", with a single strength slider (denoise 0.35–0.65) — the face is always preserved (no checkbox: that is the point of the page). **Stage 2 — Adjustments**: 11 Photoshop-style sliders in groups — Light (brightness/contrast), Levels (black point/white point/gamma), Color (saturation/temperature/R-G-B balance), Film (sharpen/vignette) — with a live server-rendered preview (debounced) and a before/after split slider. Adjustments are parameters, not baked: they survive re-applying effects. **Stage 3 — Export**: the former Export page (formats, size, quality, export presets) now applies the adjustment cascade before resize; a history-item export joins it. **Folder conveyor**: multi-select photos in the File Browser → "→ Post-Process (N)" → each photo runs the effect through the queue and is auto-exported with the adjustments into a folder chosen once (shown in the card, changeable); per-item skips are counted, interrupt cancels only this page's jobs, and names carry a run timestamp so re-runs never overwrite.
- **Post-processing engine (backend stage)**: new pure pixel-adjust package (`internal/adjust`) runs a fixed correction cascade — levels (black/white point + gamma via 256-entry LUT) → brightness → contrast (259-factor around 128) → saturation (luma mixing) → temperature (R/B gain) → per-channel balance → unsharp-mask sharpen (3×3 box blur) → radial vignette. Neutral params are bit-exact no-ops (zero-value `Params{}` is neutral: `white_point` 0/`gamma` 0 mean "unset"), alpha is preserved, all out-of-range values clamp instead of breaking, and the math is covered by table-driven tests (identity, per-stage exact values, clamp equivalences). `ExportImageParams` gains an optional `adjust` block applied after decode and before resize; new bindings `PreviewAdjust` (downscale to maxW → adjust → JPEG q85 → pure base64) and `ExportSessionItem` (export a session history item straight from its stored full-size file through the same export pipeline) join `ExportImage`, which now shares one save-to-folder helper.
- **Folder batch remix**: the File Browser gains a "Select" mode — click photos to build a selection and send them all to Remix in one go. From Image picks the list up as a "Folder: N photos" batch: the first photo loads as a preview, the Generate button becomes "Generate N photos", and every photo is enqueued once with the current settings (preset, denoise, preserve face for klein — seed +i per photo), reusing the existing batch overlay, progress and interrupt. Read/enqueue errors skip that photo with a "skipped K of N" notice (user interrupt is reported as interrupted, not skipped); replacing the preview with your own photo (drop/paste/upload/last image) drops the folder queue, and the Generate button is guarded against re-entry during the enqueue loop. Folder batch requires img2img mode (mask/inpaint is rejected with a notice).
- **FLUX.2-klein-4B support**: presets with a klein model (the new `Klein *` family mirroring the custom Flux presets at 4 steps / CFG 1) load the required Forge modules (Qwen3-4B text encoder + flux2 VAE) automatically — `forgeModulesForModel` gains a klein branch alongside moss, and `klein` joins the default `heavy_models`/`prose_models` CSVs so the memory guard and the prose prompt instruction engage explicitly rather than via the "flux" substring.
- **Virtual try-on in Edit mode**: load a garment photo (shop screenshot, catalog image) alongside your photo and the model tries it on — no instruction needed (one is generated automatically; you can still write your own). Powered by the Forge Neo ImageStitch reference mechanism: the garment image is encoded as a second reference and injected alongside the source photo. Before a try-on, the app checks free VRAM and refreshes the model to clear cached memory when the GPU is tight. The instruction field becomes optional when a reference item is loaded.
- **Preserve face in From Image (klein reference remix)**: a "Preserve face" checkbox (visible for img2img + Style mode with a klein preset selected) turns the remix into a reference generation — the Forge Neo `klein_do_reference` option injects the source image's reference KV so the face survives the restyle, with denoise 0.6–0.7 recommended by the hint; denoise above 0.9 is rejected outright (it burns the face away — live-verified). The option is enabled right before the request and reset after it (a failed reset flags the result with `preserve_identity_reset_failed`, surfaced as a warning and propagated through the queue and MCP `from_image`); in quality mode the reference is reset before the redenoise pass so the reference KV never leaks into it (a failed reset skips quality). A klein generation without preserve best-effort clears a stale enabled option, and the startup reset (app and sd-mcp) now clears both moss and klein reference options under the shared reference mutex. Validation rejects preserve identity outside preset+img2img or on a non-klein model (enqueue + entry; the MCP tool takes `preserve_identity`). The choice persists via `fi_preserve_identity`, and `sd.Client.SetOption` now accepts arbitrary JSON values (booleans for klein, strings for moss — a string "false" never disables a Python-side bool option).

## [1.0.0] — 2026-10-31

### Project
- **Renamed from SD Studio to Imagecaster** — the name now says what the tool does: it casts images from your words. Repository is [Zazza/imagecaster](https://github.com/Zazza/imagecaster) (GitHub redirects the old `sd-ai` URLs), the Go module path, binary (`imagecaster`) and all docs follow; the [sd-ai-server](https://github.com/Zazza/sd-ai-server) companion keeps its name.

### Added
- **Edit mode (instruction-based image editing)**: new `EditImage` binding runs a true reference edit on the fixed `moss_image_sft_bf16` model. The Forge Neo `moss_do_reference` option (`Moss-Image-Edit`) makes the backend inject the source image's latent into attention (reference KV at timestep zero), so the model changes what the instruction asks for and keeps the person, face, pose and scene — verified live on a 1360×2048 photo (pants→skirt applied, face untouched), and Russian instructions work natively (Qwen text encoder). The reference option is enabled right before the request and reset after it (a failed reset flags the result with `edit_reference_reset_failed`; a startup goroutine also resets it). The prompt is built as `<lora:Moss_Edit_LoRA:1.0>[style LoRAs][user LoRAs][style tags] Change only {instruction}. Keep the person, face, pose, background and composition unchanged, and keep the original lighting and color palette so the new clothing matches the photo` — the palette clause is a live-verified upgrade (a same-seed A/B moved the new garment's color/lighting match from 5/10 ("pasted on", flat light) to 8/10 (folds, window highlight, scene-consistent light)). with fixed sampler settings (Euler/Simple, 30 steps, CFG 4.0, denoise 1.0 — the reference engine reconstructs from the source instead of redrawing freely), dimensions aligned to /16 capped at 2048, kids-mode filtering and angle-tag/`<lora:`-prefix stripping on the instruction. The result lands in the session history with an "Edit: …" label; the effective prompt is shown under the result; the instruction persists via `edit_instruction`. New "Edit" page: drop/paste/last-generated source, instruction, optional seed, style selector, LoRA panel, quality checkbox, live SD progress with interrupt, download / regenerate / "edit the result" actions.
- **Edit mode joins the last-image flow**: selecting a history item works as an Edit source (auto-load on mount and on `session:selected`, like Remix), and the fullscreen viewer gets an **Edit** action next to Remix; footer viewer actions share one activate-and-navigate helper (also fixes export not highlighting the active grid item).
- **Style presets in Edit mode**: the Edit page gets a style selector listing the library's moss presets, with **"No style (model only)"** as the default. By default a selected style contributes **only its LoRAs** (shown as badges, merged with extra LoRAs from the panel, total capped at 8) — style prompt tags would restyle the whole photo, so they are opt-in via the "Apply style tags" checkbox (persisted). Distillation LoRAs (DMD) are skipped from the style contribution: a live same-seed A/B showed they degrade edit quality (4/10 vs 6/10 — waxy skin, erased fabric texture) because they are trained for 8-step CFG 1 sampling while the edit contract runs 30 steps CFG 4. The session meta records the preset id.
- **Edit mode LoRA stack**: up to 8 user LoRAs appended after the built-in edit tag; weights clamped 0–2 (NaN/Inf → 0.6), names containing `<`, `>`, `:` or control characters rejected, collapsible LoRA panel with lazy server list + datalist, persisted as `edit_loras`.
- **Edit mode quality output**: `output_mode: "quality"` (requires `resolution_id`) runs the quality chain after the edit — the reference option is reset first so the redenoise runs in normal moss mode, then the image is upscaled into the resolution box (aligned /16, capped 2048) and redenoised at 0.35; skip flags surface as warnings and the session meta records the base → upscale → redenoise chain.

### Changed
- **Forge additional modules are now managed by the app (local Forge patch removed)**: switching the SD model sends a single atomic `POST /sdapi/v1/options` carrying both `sd_model_checkpoint` and `forge_additional_modules` (new `sd.Client.SetModelWithModules`), via a single `Service.setModel` helper used by every model switch. Models matching "moss" get the fixed text-encoder + VAE module pair; everything else resets the list to empty — the hand-patched `modules_forge/main_entry.py` on the Forge Neo backend is no longer needed and has been reverted to stock (verified live: z-image → flux → moss → z-image swaps and the moss suite pass without the patch). A failed model/module switch now fails the generation instead of only logging a warning.

### Fixed
- **Neural upscale in quality mode silently degraded to CatmullRom**: `sd.Client.UpscaleImage` posted to `/sdapi/v1/extra-single-img`, an alias that 404s on the Forge Neo backend. The endpoint is now `/sdapi/v1/extra-single-image`, and the quality upscaler is resolved from the backend's upscaler list (prefers `R-ESRGAN 4x+`, falls back to `ESRGAN` on Forge Neo, whose list is None/Lanczos/Nearest/ESRGAN; resize fallback preserved). `UpscaleImage` also gained a status check and a response size limit.

## [0.9.8] — 2026-10-12

### Fixed
- **Memory guard now checks free VRAM for all models, not just the heavy white-list**: the pre-generation ollama unload only triggered for models from `heavy_models` (flux, z-image, …) before even looking at actual VRAM, so an SDXL-class checkpoint (~7 GB) sharing a 16 GB card with a warm 14B LLM was never relieved (incident 2026-10-12, riMix + ollama); free VRAM/RAM is now checked for every model — 8 GiB VRAM headroom for regular models, 12 GiB for the heavy list.

### Added
- **Image viewer: collapsible info panel + zoom**: the bottom metadata/generation-chain panel no longer covers the image — it is collapsed by default and toggled by an "ℹ" button (Remix/Export/Delete stay available without expanding, in a compact row). New zoom controls (`[−] [Fit|NN%] [+]`): fit-to-window by default (as before), 30/50/100% presets via the indicator, ±10% steps (10–500%), double-click toggles fit/100%, Ctrl+wheel zooms; when the image overflows the window it can be dragged (grab cursor, edges stay clamped to the window, bar-aware). Switching images resets to fit; zoom clamps and fit-percentage react to window resize.
- **Generation metadata in the session history**: every image in the footer history now remembers what created it — the model, LoRAs, the preset or pipeline name (Custom-mode runs show as "Custom"), and for multi-step pipelines the full per-step chain (preset, model, denoise, LoRAs; quality mode shows its base → upscale → detail chain with skipped steps omitted). Stored as a single `session_items.meta` JSON column (migration V28; old items simply have none). The model is taken from the generation context with the SD response's `sd_model_name` as fallback; oversized metadata degrades (drops LoRAs, then the chain) instead of failing. UI: thumbnail tooltip in the footer (label/model/seed/step count) plus a step-count badge, and a "Generation chain" panel in the image viewer; entries without metadata degrade to the existing fields. No new bindings — the metadata travels through the existing `GetSessionItems`.
- **Custom mode (pipeline constructor) on the Generate page**: a third generation mode (Style | Pipeline | Custom) where a multi-step pipeline is assembled inline instead of being pre-built on the Pipelines page — each step picks a preset, a denoising strength (0.05–1, steps 2+; 0 is rejected rather than silently coerced to the 0.5 default) and its own LoRA set (untouched = inherit the step preset's LoRAs, editable with the same LoRA UI as the overrides panel, "disable all" supported), up to 8 steps. The Seed field is available in Custom mode and is applied to every step, so the intended workflow is: fix the seed, then iterate on the presets/denoise of the second and later steps until the result is right. Generation goes through the existing compound engine (queue, progress, hires on the last step, interrupt all work), including batch (`seed + i`, clamped to MAX_SAFE_INTEGER on both Generate and From Image). The assembled configuration can be saved as a regular pipeline ("Save as pipeline" with name/description) — per-step LoRAs are persisted via a new `compound_preset_steps.loras` column (empty = inherit, `[]` = off; the Pipelines editor and duplicate preserve them, and they apply in all compound entry points: Generate, From Image, Test), and are included in export/import (invalid/oversized LoRA payloads are dropped on import). The editor state persists between launches (`gen_custom_steps`); untouched steps re-sync their LoRA rows from the current preset on restore (library changes don't leave stale rows). `"custom"` never leaks into From Image via shared state (sanitized to `"preset"`). Removed the now-dead "Using multi-step workflows?" toggle link.

## [0.9.7] — 2026-10-09

### Added
- **Quality mode in From Image (Remix)**: a "Quality mode" checkbox (visible for preset + img2img with a resolution selected) runs a 3-step pipeline instead of stretching the source image to the target size: img2img at the source's native size (downscale-only fit into the chosen resolution box, never upscaled) → ESRGAN neural upscale (R-ESRGAN 4x+, Catmull-Rom fallback) into the box preserving the source aspect ratio → a detail img2img pass at denoise 0.35. If the upscale or the detail pass fails, the last good image is returned with a visible notice ("Upscale skipped…"/"Detail pass skipped…"). Validation rejects quality mode outside preset+img2img or without a resolution (enqueue + entry + MCP). The mode works in batch too (3 SD operations per image), persists per page (`fi_quality_mode`), and is exposed to MCP via `from_image` props `quality`/`resolution_id`.

### Fixed
- **Hires profile is now applied in From Image Pipeline mode**: the compound (pipeline) path on From Image ignored the selected hires profile — the last step's image is now upscaled + re-denoised via the profile (same manual hires mechanism as the Generate page pipelines), including single-step pipelines; on hires failure (or when no profile is selected) the last good image is returned with its metadata (session item info / job result info) preserved.

## [0.9.5] — 2026-10-07

### Fixed
- **Forge memory-manager crashes no longer kill generations**: Forge (Neo) nulls the weakref of a torn-down lazy model object while it stays in the loaded list, so the next garbage-collection pass crashes with a 500 — `TypeError: 'NoneType' object is not callable` or `AttributeError: 'NoneType' object has no attribute 'model_size'/'model'` — and every blind retry hits the same nail (typically on img2img steps of pipelines that switch checkpoints). The SD client now detects the whole `NoneType` family in SD error responses, recovers the server state (unload checkpoint → re-select the current checkpoint, forcing a clean reload) and replays the request once — covering txt2img, img2img and every pipeline step. The local Forge install is also patched at the root: a `_safe_real_model` helper on every direct call site, `is_dead` treats finalized objects as dead, and the size helpers return 0 for a missing model, so the broken object can never crash the GC again (patches are reinstall-on-upgrade, tracked in the project memory).
