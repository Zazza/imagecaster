# Changelog

All notable changes to SD Studio are documented here.

## [Unreleased]

### Fixed
- **Edits stopped applying on large (phone) photos — instruction binding is resolution-dependent**: a live experiment with an identical prompt/config showed the edit applies at canvases up to ~1408px on the long side (832×1248, 832×1280, 928×1408 all work) and silently does nothing from 1024×1536 and up (1360×2048 — a typical phone photo after alignment — leaves the clothes untouched and only drifts the face). The edit LoRA is trained around 1024 and doesn't bind instructions to larger canvases. The edit now runs on a canvas capped at **1408** (aligned /16, floor 64); when the source is larger, the result is upscaled back to the source's aligned size with the resolved neural upscaler after the edit (≈6s for 2048px, resize fallback on failure — the edited canvas is kept). Verified live end-to-end on a 1360×2048 source: edit on 928×1408 → ESRGAN back to 1360px — the requested pants-to-skirt change applied, face/pose/scene preserved.
- **Edit mode was silently regenerating the scene instead of editing it**: the Forge `moss_do_reference` option the flow toggled around every edit turned out to be a phantom — the A1111/Forge options API accepts any key in a POST and stores it, but no code on the backend ever reads it (verified by grepping the entire Forge tree; the real Moss-Image-Edit mechanism is reference KV-cache injection implemented by custom ComfyUI node packs, which Forge does not have). Combined with denoise 1.0 — where img2img ignores the init image entirely — every edit rebuilt the person and background from scratch (the old mode only *looked* like it preserved the photo because the Keep-formula guided a full redraw; the face was re-imagined, not preserved). The edit contract is now a plain img2img at **denoise 0.65** (verified with a live denoise matrix + vision checks: 0.5–0.55 = edits don't apply, 0.65 = full edit with pose and background preserved, 0.8 = background drift, 1.0 = full regeneration — the slider max reproduces the old redraw behaviour on purpose); all the reference-option machinery (enable/reset/deferred reset, startup reset, `edit_reference_reset_failed` warning) is removed along with the now-unused `sd.Client.SetOption`.
- **Non-English edit instructions never applied (moss understands English only)**: a live experiment showed even a fully specific Russian instruction does nothing ("замени платье" style inputs produced no change at all), while the same instruction in English applies precisely. The edit flow now auto-translates non-ASCII instructions into a concrete English edit phrase via the configured generation LLM (same model resolution as prompt generation; 1024-token budget so thinking models finish their reasoning, think-blocks stripped, lora-tag/quote/newline sanitized, graceful fallback to the original text on any LLM failure). Verified live end-to-end: a Russian "надень красное вечернее платье" instruction became "the blue floral dress to a long red evening gown" and the edit applied with the face and scene preserved. The session label keeps the original instruction text.

### Added
- **Edit mode joins the last-image flow**: selecting a history item now also works as an Edit source — the Edit page loads the active session image on mount (same as Remix) and reloads it when another item is picked from the history while the page is open (`session:selected`), with the usual latest-wins guard. The fullscreen viewer gains an **"Edit" (Правка) action** next to Remix; the footer's viewer actions now share one activate-and-navigate helper (which also fixes the export action not highlighting the active item in the grid). `session:added`/`session:active` still never auto-load — generating on Edit keeps your source image.
- **Style presets in Edit mode**: the Edit page gets a style selector listing the library's moss presets, with **"No style (model only)"** as the default — exactly the previous plain behaviour. A selected preset contributes its prompt tags (angle-tag/lora-prefix sanitized, capped), its LoRAs (shown as badges, merged with any extra LoRAs from the panel, total capped at 8) and its sampler settings (steps 1–50, CFG ≤10; moss presets carry the 8-step DMD configuration, which makes a full edit take ~8s instead of ~30-45s — verified live at quality parity). The session history records the preset id in the generation meta.
- **Edit strength slider**: the edit denoise is now exposed (0.3–1.0, default 0.65) and persisted, so strong edits can push towards 0.8 while gentle retouching can drop to 0.5. The quality chain (upscale + redenoise) uses the effective style steps — a full style+quality edit at 2048px completes in ~32s live.

### Changed
- **Forge additional modules are now managed by the app (local Forge patch removed)**: switching the SD model sends a single atomic `POST /sdapi/v1/options` carrying both `sd_model_checkpoint` and `forge_additional_modules` (new `sd.Client.SetModelWithModules`), via a single `Service.setModel` helper used by every model switch (Generate, queue, From Image, pipelines, upscale, Test, MCP, Edit). Models matching "moss" get the fixed text-encoder + VAE module pair (constants in `internal/generation/edit.go`); everything else explicitly resets the list to empty — so the hand-patched `modules_forge/main_entry.py` on the Forge Neo backend is no longer needed and has been reverted to stock (verified on the live server: z-image → flux → moss → z-image swaps, the moss generation suite and the Edit flow all pass without the patch). A failed model/module switch now fails the generation instead of only logging a warning — the queue retries such jobs per its recovery policy instead of silently generating with the previous model.

### Added
- **Edit mode (instruction-based image editing)**: new `EditImage` binding sends the source image to img2img on the fixed `moss_image_sft_bf16` model. The prompt is built as `<lora:Moss_Edit_LoRA:1.0>[user LoRAs][style tags]Change only {instruction}. Keep the person, face, pose, background and composition unchanged.`; the base sampler settings are Euler/Simple, 30 steps, CFG 4.0, denoise 0.65 (see the edit-strength slider above), the source dimensions are rounded to a multiple of 16 (floor 64) with proportional downscale when a side exceeds 2048, and the instruction goes through kids-mode input filtering (max 2000 chars, angle tags and residual `<lora:` prefixes stripped). The result lands in the session history with an "Edit: …" label (plus the style preset id when one is selected). The last instruction persists via the new `edit_instruction` setting. New "Edit" page in the sidebar (Create group): drop/paste/last-generated source, instruction textarea (persisted), optional seed, style selector, strength slider, LoRA panel, quality checkbox, live SD progress with interrupt, download / regenerate / "edit the result" (output becomes the next source) actions; session items from edits are labeled "Edit" in the footer history.
- **Edit mode LoRA stack**: `EditImage` accepts up to 8 user LoRAs appended after the built-in edit tag — `<lora:Moss_Edit_LoRA:1.0> <lora:name:weight>Change only …` (verified live: the Detail_Boost_Moss@0.8 stack works). Weights are clamped to 0–2 (NaN/Inf → 0.6), names containing `<`, `>`, `:` or control characters are rejected (an unpaired `<` bypasses pair-stripping and would inject a second lora tag), and an empty name is rejected. The Edit page gets a collapsible LoRA panel (lazy-loaded server list via `GetSDLoRAs` + datalist autocomplete, add/remove rows capped at 8, weight 0–2) persisted as the new `edit_loras` setting.
- **Edit mode quality output**: `output_mode: "quality"` on `EditImage` (requires `resolution_id`, validated upfront) runs the proven From Image quality chain after the edit — the image is upscaled into the resolution box (kept a multiple of 16, capped at 2048 per the moss contract) and redenoised at 0.35 with the effective edit sampler settings. `quality_upscale_skipped` / `quality_redenoise_skipped` surface as warnings in the UI, and the session meta records the base → upscale → redenoise chain. UI: quality checkbox + resolution selector (checkbox disabled until a resolution is picked), persisted via `edit_quality_mode` / `edit_resolution_id`.

### Fixed
- **Neural upscale in quality mode silently degraded to CatmullRom**: `sd.Client.UpscaleImage` posted to `/sdapi/v1/extra-single-img`, an alias that returns 404 on Forge Neo — quality mode then quietly fell back to a plain resize. The endpoint is now `/sdapi/v1/extra-single-image` (verified live: ESRGAN ×2 → 2048px in ~14s). The quality upscaler is also no longer the hardcoded `R-ESRGAN 4x+` (absent from Forge Neo, whose list is None/Lanczos/Nearest/ESRGAN): it is resolved from the backend's own upscaler list, preferring `ESRGAN` and falling back to `R-ESRGAN 4x+` for the older Forge backend, with the resize fallback preserved if neither is present.

## [0.9.8] — 2026-10-12

### Fixed
- **Memory guard now checks free VRAM for all models, not just the heavy white-list**: the pre-generation ollama unload only triggered for models from `heavy_models` (flux, z-image, …) before even looking at actual VRAM, so an SDXL-class checkpoint (~7 GB) sharing a 16 GB card with a warm 14B LLM was never relieved (incident 2026-10-12, riMix + ollama); free VRAM/RAM is now checked for every model — 8 GiB VRAM headroom for regular models, 12 GiB for the heavy list.

### Added
- **Image viewer: collapsible info panel + zoom**: the bottom metadata/generation-chain panel no longer covers the image — it is collapsed by default and toggled by an "ℹ" button (Remix/Export/Delete stay available without expanding, in a compact row). New zoom controls (`[−] [Fit|NN%] [+]`): fit-to-window by default (as before), 30/50/100% presets via the indicator, ±10% steps (10–500%), double-click toggles fit/100%, Ctrl+wheel zooms; when the image overflows the window it can be dragged (grab cursor, edges stay clamped to the window, bar-aware). Switching images resets to fit; zoom clamps and fit-percentage react to window resize.
- **Generation metadata in the session history**: every image in the footer history now remembers what created it — the model, LoRAs, the preset or pipeline name (Custom-mode runs show as "Custom"), and for multi-step pipelines the full per-step chain (preset, model, denoise, LoRAs; quality mode shows its base → upscale → detail chain with skipped steps omitted). Stored as a single `session_items.meta` JSON column (migration V28; old items simply have none). The model is taken from the generation context with the SD response's `sd_model_name` as fallback; oversized metadata degrades (drops LoRAs, then the chain) instead of failing. UI: thumbnail tooltip in the footer (label/model/seed/step count) plus a step-count badge, and a "Generation chain" panel in the image viewer; entries without metadata degrade to the existing fields. No new bindings — the metadata travels through the existing `GetSessionItems`.
- **Custom mode (pipeline constructor) on the Generate page**: a third generation mode (Style | Pipeline | Custom) where a multi-step pipeline is assembled inline instead of being pre-built on the Pipelines page — each step picks a preset, a denoising strength (0.05–1, steps 2+; 0 is rejected rather than silently coerced to the 0.5 default) and its own LoRA set (untouched = inherit the step preset's LoRAs, editable with the same LoRA UI as the overrides panel, "disable all" supported), up to 8 steps. The Seed field is available in Custom mode and is applied to every step, so the intended workflow is: fix the seed, then iterate on the presets/denoise of the second and later steps until the result is right. Generation goes through the existing compound engine (queue, progress, hires on the last step, interrupt all work), including batch (`seed + i`, clamped to MAX_SAFE_INTEGER on both Generate and From Image). The assembled configuration can be saved as a regular pipeline ("Save as pipeline" with name/description) — per-step LoRAs are persisted via a new `compound_preset_steps.loras` column (empty = inherit, `[]` = off; the Pipelines editor and duplicate preserve them, and they apply in all compound entry points: Generate, From Image, Test), and are included in export/import (invalid/oversized LoRA payloads are dropped on import). The editor state persists between launches (`gen_custom_steps`); untouched steps re-sync their LoRA rows from the current preset on restore (library changes don't leave stale rows). `"custom"` never leaks into From Image via shared state (sanitized to `"preset"`). Removed the now-dead "Using multi-step workflows?" toggle link.

## [0.9.7] — 2026-10-09

### Added
- **Quality mode in From Image (Remix)**: a "Quality mode" checkbox (visible for preset + img2img with a resolution selected) runs a 3-step pipeline instead of stretching the source image to the target size: img2img at the source's native size (downscale-only fit into the chosen resolution box, never upscaled) → ESRGAN neural upscale (R-ESRGAN 4x+, Catmull-Rom fallback) into the box preserving the source aspect ratio → a detail img2img pass at denoise 0.35. If the upscale or the detail pass fails, the last good image is returned with a visible notice ("Upscale skipped…"/"Detail pass skipped…"). Validation rejects quality mode outside preset+img2img or without a resolution (enqueue + entry + MCP). The mode works in batch too (3 SD operations per image), persists per page (`fi_quality_mode`), and is exposed to MCP via `from_image` props `quality`/`resolution_id`.

### Fixed
- **Hires profile is now applied in From Image Pipeline mode**: the compound (pipeline) path on From Image ignored the selected hires profile — the last step's image is now upscaled + re-denoised via the profile (same manual hires mechanism as the Generate page pipelines), including single-step pipelines; on hires failure (or when no profile is selected) the last good image is returned with its metadata (session item info / job result info) preserved.
- **Fields no longer vanish when the gen-mode toggle is on "Pipeline"**: on From Image, the Seed field and the "Quality mode" checkbox used to disappear entirely in Pipeline mode (looking like the feature doesn't exist — the choice is also persisted between launches). They now stay visible but dimmed and disabled with an "Available in Style mode only" hint; the 3-operations hint only shows when the checkbox is actually usable. Regression-tested (6 vitest cases).
- **Huge results are no longer silently dropped from the session**: `AddToSession` re-encodes images over the 50 MB base64 cap to JPEG (Q95) instead of quietly discarding them — reachable via quality mode at 4K resolutions; a failed re-encode now logs a warning before dropping.

## [0.9.6] — 2026-10-08

### Added
- **Window icon**: the title-bar/taskbar window icon now uses the app logo (a dedicated 256×256 PNG embedded via `go:embed` and wired into the Wails Linux options — the 1024px packaging icon stays for builds/installers).
- **Local builds stamp their version**: `make build` passes `-ldflags "-X main.version=$(git describe --tags --abbrev=0)"`, so a locally built binary shows the real version (e.g. v0.9.5) instead of "vdev"; CI releases already stamped it.
- **Resolution picker in From Image (Remix)**: the params block (next to Denoising/Seed) now has a `ResolutionSelector` with a leading "Match original" option — `null` keeps the current behavior (backend stores the original size), picking a resolution sends `resolution_id` in `EnqueueFromImage` params (backend fits the original into the chosen resolution preserving aspect ratio, upscaling included). The choice is page-local and is not persisted.

### Changed
- **Safer destructive buttons**:
  - Queue "Cancel All" now requires a second click ("Cancel?" confirm state, resets after 3 s), same as "Clear Done".
  - Queue footer buttons got a stable `min-width` (wider for the morphing clear button) plus `white-space: nowrap`, so the "…→ confirm?" text morph no longer changes button size or shifts neighbors.
  - Session "Delete History" in the footer shows a native `window.confirm()` dialog ("Delete the session and all its files? This action cannot be undone.") after the inline two-click confirm, before files are removed; the button width is also fixed.
  - New i18n keys in both RU and EN: `fi.resolution_original`, `queue.confirm_cancel`, `footer.confirm_delete_dialog`.

## [0.9.5] — 2026-10-07

### Fixed
- **Forge memory-manager crashes no longer kill generations**: Forge (Neo) nulls the weakref of a torn-down lazy model object while it stays in the loaded list, so the next garbage-collection pass crashes with a 500 — `TypeError: 'NoneType' object is not callable` or `AttributeError: 'NoneType' object has no attribute 'model_size'/'model'` — and every blind retry hits the same nail (typically on img2img steps of pipelines that switch checkpoints). The SD client now detects the whole `NoneType` family in SD error responses, recovers the server state (unload checkpoint → re-select the current checkpoint, forcing a clean reload) and replays the request once — covering txt2img, img2img and every pipeline step. The local Forge install is also patched at the root: a `_safe_real_model` helper on every direct call site, `is_dead` treats finalized objects as dead, and the size helpers return 0 for a missing model, so the broken object can never crash the GC again (patches are reinstall-on-upgrade, tracked in the project memory).

## [0.9.3] — 2026-10-06

### Changed
- **Searchable style picker in the pipeline editor**: the per-step preset `<select>` on the Pipelines page (300+ entries in one flat list) is replaced by a reusable `SearchableSelect` combobox — type to filter by preset name or style type (hint on the right), full keyboard navigation (arrows + Enter, Esc cancels and restores the chosen label, ✕ clears the step back to "no style"). Pure Vue, no dependencies; other selects are untouched.
